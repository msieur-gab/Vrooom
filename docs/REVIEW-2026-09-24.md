# Code review — 2026-09-24

An audit of the app as a whole, done before planning fixes. Nothing was
changed while writing it. Each item says what is wrong, where, and what the
fix looks like. Sections are in the order to work through them; tick items
off as they land. Line numbers are as of commit `63fcbc4`.

Longer-standing items already live in `TODO.md` and are only referenced here.

## 1. Bugs — fix first

- [ ] **The garage car loads twice on every launch.** `init()` calls
  `showScreen('garage-screen')`, which already runs `updateGarageScreen()`,
  then calls `updateGarageScreen()` again (`js/app.js:101-103`); `saveProfile`
  does the same (`app.js:394-396`). Both `loadCar` calls start before either
  finishes, so both car groups end up in the scene and both tap handlers
  stay attached: a tap plays its sound twice, and shake and lights move only
  one of the two cars. Fix: drop the extra calls, and make `loadCar` in the
  viewer discard a load that a newer one has overtaken.

- [ ] **A tag tapped while offline shows "Not found".** The service worker
  looks up `/vrooom/?car=vroom` including the query, finds nothing, and
  answers its 404 text (`sw.js:148-158`). The core moment — tap the car at a
  playground with no signal — breaks. Fix: for navigation requests, serve the
  cached `index.html` whatever the query.

- [ ] **Check-in only sees places the map has shown.** `ensureArea` reads
  places from the tiles MapLibre has loaded for the current view
  (`services/playground.js:666`), and the map only centres itself the first
  time it opens. Open the map at home, walk 2 km, tap "I'm here!" → "No
  playground within 150m". Fix: move the map to the fresh GPS fix (zoom 15)
  before reading; `placesInView` already waits for the tiles.

- [ ] **Import leaves a blank screen.** `showScreen('garage')` should be
  `'garage-screen'` (`app.js:828`), so every screen gets hidden. The car
  picture, side profiles and sounds are not reloaded from settings either.

- [ ] **NFC Cancel does not stop the scan.** `stopScan()` only drops the
  reader (`services/nfc.js:69`); a Web NFC scan stops only through an
  `AbortController` signal passed to `scan()`. The old scan keeps listening,
  and its pending promise can resolve later and load a car nobody asked for.

- [ ] **The fallback when GPS fails never works.** It calls
  `displayResults()` while `userCoords` is still null; the crash is swallowed
  by the empty `catch` (`app.js:432-438`). It is also hard-coded to Munich.
  Fix: show the cache around the last known position, or none.

## 2. Security — place names go into HTML unescaped

- [ ] `shared/badge-svg.js` puts the place name straight into SVG markup,
  which the app (`renderBadges`) and `connect.html` insert with `innerHTML`.
  Two ways in: an OSM edit that names a playground `<img src=x onerror=…>`
  runs code in the app after a check-in there (with access to the child's
  data); anyone who sees a QR code can post their own payload and run code
  on the parent's computer. Fix: a small escape function in `badge-svg.js`.
- [ ] The relay lets a second POST overwrite the first
  (`netlify/functions/session.js`, `server/php/session.php`). Make a session
  writable once.

## 3. Sound — one module instead of three

Sound is played from three places that don't know about each other:
`playSound` in `app.js` (a new `Audio` each time), an `audioMap` per viewer
(`car-viewer/interaction.js`), and the engine borrowing the viewer's "Body"
player and setting it to loop (`car-viewer/vibration.js:71`) — so tapping
another part while the engine runs silences the engine while the car keeps
shaking.

`<audio>` elements cause the rest: a delay before the sound on phones, a gap
each time the engine loop restarts, `volume` ignored on iPhone, and range
requests, which is why `sw.js` needs `rangeFromCache`.

- [ ] One `js/services/sound.js` on the Web Audio API: one context resumed
  on the first tap, each file fetched and decoded once and kept by URL,
  sounds that start instantly and can overlap, a seamless engine loop, gain
  that works on iPhone. Whole-file fetches let `rangeFromCache` go.
- [ ] Do it together with the sound-size item in `TODO.md`: decoded audio
  costs about 10 MB of memory per minute. `default_click.mp3` is 3 s at
  256 kbps; the Dodge engine is 24 s where a 2–3 s loop would do. Trimmed,
  mono, ~64 kbps: the 8 sounds in use go from 1.8 MB to about 0.3 MB — and
  preloading them at install becomes cheap, which settles that TODO.
- [ ] 7 of the 15 files in `sounds/` (~1.5 MB) are used by no car.

## 4. Car loading and rendering

- [ ] **Store the car id, not the config path.** `db.addCar` saves
  `configUrl` (`app.js:304`) — the database repeats the mistake the tag
  contract fixed, and the planned `cars/<id>/car.json` move breaks every
  saved car. `addCar` also adds a new row on every pick, so the table fills
  with duplicates.
- [ ] **Keep parsed models.** Every garage visit re-fetches, re-parses and
  rebuilds the car (`updateGarageScreen`), and both cars share the same five
  STL files. A geometry cache by URL makes switching instant.
- [ ] **Lighter on cheap phones.** Each viewer has its own WebGL renderer
  with a 2048 px soft shadow and `preserveDrawingBuffer: true`
  (`car-viewer/scene.js`); capture copies right after rendering and doesn't
  need that flag. A new user can end up with three renderers. 1024 px
  shadows look the same on a phone.
- [ ] **Small leaks.** Headlight cones are never disposed when lights go
  off (`car-viewer/headlights.js:27`). A viewer removed and re-added to the
  page is dead: `_initialized` stays true after `destroy()`.
- [ ] `vibrationAmplitude` in the car files is never read.
- Note: `toOutline()` (colouring-book outline) is unused but is the most
  physical-first feature in the viewer — keep it for the badges/print path.

## 5. Offline (service worker)

- [ ] Split the one versioned cache: app files (versioned), sounds and
  models (kept), tiles (kept, capped — see `TODO.md`). Today every
  `CACHE_NAME` bump throws away sounds, models and tiles.
- [ ] Dexie, Leaflet, MapLibre and three.js come from unpkg/jsDelivr and are
  fetched network-first: every launch waits on a weak signal, and anything
  not re-fetched since the last update is missing offline. Dexie is used as
  soon as `database.js` loads, so without it the app does not start. Vendor
  them (in `TODO.md`) and precache.
- [ ] Load MapLibre (~800 KB) the first time the map opens, not on every
  launch.
- [ ] The `PRECACHE` list is kept by hand; a new module left off it breaks
  the app offline. A small checker in `tools/`.
- [ ] Dead: the Overpass branch in `sw.js`, `services/overpass.js`, the
  unused helpers in `database.js` (`hasCheckedIn`, `selectCar`, …), and
  `print.html`, which nothing links to.

## 6. Installing on phones

- [ ] No `<link rel="apple-touch-icon">`: the iPhone home-screen icon falls
  back to a screenshot — and installing is the decided iPhone path.
- [ ] No `"purpose": "maskable"` icon: Android puts it on a white square.
- [ ] No `id` in the manifest. Set it before release; changing `start_url`
  later would make phones see a different app.
- [ ] "Scan Your Car" shows on iPhone and then says NFC is not supported.
  Hide it when `NDEFReader` is missing.

## 7. Against the project's own decisions — Gab's call

- [ ] The emoji avatar picker (`AVATARS`) contradicts "the car IS the kid's
  identity — no avatar".
- [ ] PWAPulse pings `pwa-pulse.netlify.app` on every visit/launch.
  Anonymous, but it contradicts "zero tracking" as written.
- [ ] Badges are keyed by coordinates rounded to 3 decimals
  (`services/checkin.js:25`): two playgrounds in the same ~100 m cell share
  one badge. The OSM id is now available and is the natural key.

## 8. Structure

- [ ] `app.js` (855 lines) runs five screens plus printing. Split by screen
  (garage, map, badges, print) plus a `cars.js` for the car list,
  `carFromUrl`, loading and sound lookup — which fits one folder per car.
